# Resume Optimizer AI Agent

Tailor a resume to a specific job posting. Upload a resume PDF, paste a job URL, and get an aligned, ATS-friendly PDF plus a match score, suggested bullet rewrites and a list of missing skills.

> Status: demo / portfolio project. The match score is generated by a language model and is not a validated measure of ATS performance. Always review generated resumes for accuracy before sending them.

## How it works

```
Resume PDF + job URL
        |
        v
 1. Validate the PDF (type, 10 MB limit, not empty)
 2. Scrape the job posting to markdown (Crawl4AI + Playwright)
 3. Extract resume text (pdfplumber)
 4. LLM #1: extract structured job data
      role title, hard skills, responsibilities, keywords to mirror
 5. LLM #2: align the resume to the job
      match score (0-100), pivoted bullets (original / suggested / reason),
      full reconstruction, missing skills
 6. Normalize: candidate flow, section order, bullet importance
 7. Render HTML (Jinja2, Harvard-style template) -> PDF (wkhtmltopdf)
 8. Upload the PDF to Cloudflare R2 and save a history record in Supabase
        |
        v
 Results + expiring download link
```

## Features

- Job posting scraping from any URL, with a 60-minute in-memory cache for scraped text and extracted job data.
- Schema-validated LLM output (Pydantic parsers, JSON mode) with up to 3 attempts and correction prompts that include the previous error.
- Rule-based normalization: estimates years of experience from dates, detects management experience, infers domain tags, and chooses a candidate flow (new grad, early, mid or senior; IC or manager). Each flow sets the summary length, section order, bullets per entry and whether older roles are collapsed. Bullets are scored by numbers, action verbs and outcomes, and the strongest are highlighted.
- User control: per-request overrides (flow, years of experience, manager flag, domain tags, top skills, include/exclude sections) and saved preference profiles with a default profile.
- Per-user history with PDF downloads (presigned URLs that expire after 1 hour by default) and deletion.
- Google sign-in through Supabase; backend validates Supabase JWTs with the project's JWKS.
- Dark/light theme, drag-and-drop upload and a results view with the match score and suggested bullets.

## Tech stack

| Layer | Technology |
|---|---|
| Backend | Python 3.11, FastAPI, Uvicorn, Pydantic, python-jose, httpx |
| AI | LangChain + OpenAI-compatible client via OpenRouter (default model `google/gemini-3-flash-preview`) |
| Scraping and PDF | Crawl4AI, Playwright, pdfplumber, Jinja2, pdfkit + wkhtmltopdf |
| Data and storage | Supabase (auth and Postgres), Cloudflare R2 (S3-compatible, boto3) |
| Frontend | React 19, TypeScript, Vite, TanStack Router, Tailwind CSS 4, shadcn/ui (Radix), Supabase Auth UI |
| Deployment | Docker (multi-stage backend image, nginx frontend image), suitable for Coolify-style hosting |

## API

| Method | Path | Purpose |
|---|---|---|
| POST | `/resume/full-alignment?url=...` | Run the full workflow (multipart upload: `file`, optional `overrides`, `preference_id`) |
| GET | `/resume/generate-download-url` | Create an expiring download URL for a generated PDF |
| GET / DELETE | `/history`, `/history/{record_id}` | List or delete past results (and their PDFs) |
| GET / POST / PUT / DELETE | `/user/preferences...` | Manage saved preference profiles; `POST .../{id}/default` sets the default |
| GET | `/health` | Health check |

Interactive docs are available at `/docs` when `ENVIRONMENT=development`.

## Getting started

### Prerequisites

- Python 3.11, Node.js 20+, and `wkhtmltopdf` installed on the machine
- A Supabase project, a Cloudflare R2 bucket and an OpenRouter API key

### Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp ../.env.example .env        # then fill in your own values
uvicorn app.main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

### Docker

Each of `backend/` and `frontend/` has its own Dockerfile. Pass the variables from `.env.example` at runtime. Never commit real keys.

### Configuration

Copy `.env.example` and set at least: `SUPABASE_URL`, `SUPABASE_KEY`, `OPENROUTER_API_KEY`, the `R2_*` values, and for the frontend `VITE_SUPABASE_URL`, `VITE_SUPABASE_KEY` and `VITE_BACKEND_URL`. Optional settings include `AI_MODEL`, `AI_TEMPERATURE`, `AI_MAX_TOKENS`, PDF page margins, `CORS_ORIGINS` and `DOWNLOAD_URL_EXPIRY`.

## Project structure

```
backend/
  app/
    agents/        # extraction and alignment LLM agents
    api/routes/    # auth, resume, history, preferences
    core/          # settings, security (JWT), exceptions, logging
    generators/    # HTML -> PDF generation
    models/        # Pydantic schemas, Supabase client
    repositories/  # database access (history, preferences)
    services/      # resume workflow, R2 storage, auth
    utils/         # resume normalizer (candidate flows, bullet scoring)
  templates/harvard.html
frontend/
  src/features/dashboard/   # upload, job URL, preferences, results, history
  src/routes/ , src/lib/    # routing, API client, Supabase client
```

## Limitations

- Generated content can contain errors or reword facts; review before use.
- No automated tests are included yet.
- Job-site scraping can fail on pages that block bots or need a login.
- Authentication hardening is incomplete (for example, token audience verification is disabled).
